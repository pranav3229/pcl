# PCL v0.1.0-alpha Release Notes
**Initial Public Alpha Release of the Physical Capability Language Standard**

---

## 1. What is PCL?

The **Physical Capability Language (PCL)** is an open, machine-readable protocol for describing physical capabilities and physical intents.

PCL provides a vendor-neutral interoperability layer that sits *above* native communication protocols (such as ROS 2, OPC-UA, and HTTP REST). It allows Physical AI agents and dispatchers to discover capabilities, express demand, deterministically match providers, map parameters to native execution commands, and cryptographically verify outcome evidence.

---

## 2. What is Included in v0.1.0-alpha

- **Normative Wire Specification:** [`spec/SPEC.md`](../../spec/SPEC.md) & [`spec/MATCHING.md`](../../spec/MATCHING.md).
- **JSON Schema Draft 2020-12 Definitions:** Schemas for Entity, CapabilityDeclaration, CapabilityOffer, Intent, and Evidence.
- **Deterministic 8-Gate Matcher:** Math-grounded evaluation covering goals, inputs, outputs, generalized constraints (Quantity, Range, Set, Value), spatial proximity, runtime state, and availability.
- **Language-Agnostic Conformance Test Suite:** Portable JSON fixtures in [`spec/conformance/`](../../spec/conformance/) validating matching, Haversine spatial math, parameter mapping, RFC 8785 JCS canonicalization, and Ed25519 / ECDSA signatures.
- **Python Reference SDK & CLI:** Reference models, matcher, parameter resolver, and verification engine under `sdk/python/`.
- **Developer Documentation & Quickstart:** Complete 10-minute tutorial, architecture deep-dive, and clean-room implementation guide.

---

## 3. What is NOT Included (Explicit Non-Goals)

To prevent premature abstraction and maintain protocol focus, the following are **intentionally excluded** from v0.1.0-alpha:
- **No Distributed / Hosted Registry:** PCL currently defines local registry data formats; cloud registry indexing and federation will be developed in future application-layer milestones.
- **No Robot Kinematics / Motion Controllers:** PCL does not compute motor trajectories, inverse kinematics, or PID loops.
- **No Workflow DAG Orchestration:** Multi-agent dependency graphs belong in external orchestration platforms (Temporal, Airflow).
- **No Native Protocol Drivers in Core:** PCL does not run ROS 2 nodes or HTTP servers directly; parameter payloads are dispatched via external adapters.
- **No Blockchain, Tokenomics, or Escrow:** PCL uses standard asymmetric cryptography and content-addressed digests.

---

## 4. Who Should Try PCL v0.1.0-alpha?

- **Physical AI & Autonomous Agent Developers:** Teams building AI dispatchers that need a structured, deterministic way to query what physical robots can do.
- **Robotics Fleet Software Engineers:** Teams seeking a standardized abstraction layer to expose capabilities across heterogeneous robot fleets without hardcoding proprietary topic schemas.
- **Standards Implementers:** Developers interested in building independent clean-room SDKs in Rust, Go, TypeScript, or C++.

---

## 5. What is Experimental?

- **Protocol Version:** `0.1.0-alpha` reflects an early draft standard. Minor schema adjustments may occur based on community feedback prior to `v1.0.0`.
- **Domain Vocabularies:** Example vocabularies (e.g. `https://pcl.dev/vocab/logistics/v0`) are illustrative test URIs. Official vocabulary governance working groups will be established.

## 6. How to Get Started

Follow the [Developer Quickstart](../QUICKSTART.md) to install the reference SDK, run matching, and verify evidence:

```bash
git clone https://github.com/pranav3229/pcl.git
cd pcl/sdk/python
pip install -e ".[dev]"
python -m pcl.cli match ../../spec/examples/intent-package-transport.json
```
